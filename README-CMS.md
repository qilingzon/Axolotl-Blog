# 美西螈 CMS 部署教程（小白版）

> **目标**：跟着点鼠标，15 分钟把博客后台部署上线。全程只需要一台电脑 + 浏览器。
> **部署完之后**：打开 `你的域名/admin/` → 登录 → 写文章 → 点发布 → 1 分钟后自动上线，没有别的步骤。
> 已经部署过、只是来查问题的，直接拉到「常见问题」。

## 开始前

- 📱 建议用**电脑**操作（要登录腾讯云和 GitHub 两个网站）
- 你的博客仓库是 GitHub 上的 `qilingzon/Axolotl-Blog`（不用管它，教程会带你去连）

---

## 第 0 步：跑一键配置脚本（约 2 分钟）

这一步不用动脑子——脚本会问你 3 个问题、帮你生成密钥、检查令牌，最后打印 4 行「待会儿要粘贴的内容」。

1. 打开终端（Windows 用 Git Bash 或 PowerShell），进入博客目录，运行：

   ```bash
   node scripts/cms-setup.mjs
   ```

2. 按提示回答：
   - **用户名**：给后台起个登录名（直接回车 = `axolotl-admin`）
   - **密码**：至少 8 位，输完屏幕上会显示，记到安全的地方
   - **仓库/分支**：直接回车走默认
   - **GitHub 令牌**：脚本会自动检测并验证；检测不到时给你一个链接，照屏幕上的 3 句话点一遍、把令牌粘贴回去即可

3. 跑完你会看到一个这样的方块，**先别关窗口**：

   ```
   ┌─ 复制这 4 行（变量名 = 值）──────────────
   │ CMS_USERNAME = ……
   │ CMS_PASSWORD = ……
   │ CMS_SESSION_SECRET = ……
   │ CMS_GITHUB_TOKEN = ghp_……
   └──────────────────────────────
   ```

   ⚠️ 这 4 行里有密码和令牌：不要发给别人、不要截图外传。

> ✅ **到这里你应该看到**：绿色 ✓ 的令牌验证提示 + 上面那个 4 行方块。
> 如果令牌验证一直失败：90% 是创建时漏勾了权限，重新打开脚本给的链接再生成一次（记得勾 `repo`）。

---

## 第 1 步：在 EdgeOne Pages 创建项目（约 5 分钟）

1. 浏览器打开 **https://console.cloud.tencent.com/edgeone/pages**
   - 没有腾讯云账号？微信扫码登录即可
2. 点 **「创建项目」** → 选 **「从 Git 仓库导入」**（第一次会让你授权 GitHub，点同意授权）
3. 选中仓库 `Axolotl-Blog`，按下表填写（**其余保持默认**）：

   | 项目 | 填什么 |
   |---|---|
   | 构建命令 | `npm run build` |
   | 输出目录 | `dist` |
   | 生产分支 | `master` |

4. **先别点部署**——下一步要先加环境变量。

> ✅ **到这里你应该看到**：仓库出现在创建页里，三个框都按表格填好了。

---

## 第 2 步：粘贴 4 个环境变量，部署（约 2 分钟）

1. 在创建页找到 **「环境变量」** 区域（或在 项目设置 → 环境变量），把第 0 步方块里的 4 条**逐条添加**：
   - 变量名照抄（如 `CMS_USERNAME`），值从方块里复制
   - 注意复制时**别带上前后空格**
2. 保存后点 **「部署」**（已创建过的点「重新部署」）
3. 等构建完成，一般 1–3 分钟，页面会显示部署成功

> ✅ **到这里你应该看到**：部署列表里出现绿色的「部署成功」。

---

## 第 3 步：验收（约 2 分钟）

- [ ] 打开 `https://你的域名/admin/`，能看到粉色美西螈登录页
- [ ] 用第 0 步设置的用户名密码能登录，欢迎语显示你的用户名
- [ ] 写一篇测试文章点「发布」→ 1 分钟后博客首页能看到它
- [ ] 没问题的话，把这篇测试文章删掉 🗑

**到此部署完成。** 日常写文章只有三个动作：打开后台 → 写 → 点发布。

## 常见问题（按症状查）

| 症状 | 原因与解法 |
|---|---|
| 构建失败 | 打开部署日志看报错；最常见是环境变量漏加或值里粘了多余空格 |
| 登录提示「CMS 尚未配置」 | 4 个环境变量没加全，或加了没点「重新部署」 |
| 登录提示令牌/权限相关错误 | 重跑第 0 步脚本拿一个新令牌，回 EdgeOne 只更新 `CMS_GITHUB_TOKEN`，再点「重新部署」 |
| 忘记密码 | EdgeOne 环境变量里改 `CMS_PASSWORD` → 点「重新部署」，用新密码登录 |
| 连续输错 5 次被锁 | 等 15 分钟自动解锁；等不及就在 EdgeOne 点「重新部署」立即解锁 |
| 发布后前台没变化 | 正常，构建约 1 分钟，刷新再等一下；仪表盘的数字变了就说明保存成功了 |
| 想在本地先试试 | `npm run build && node scripts/cms-dev.mjs` → 打开 http://localhost:8090/admin/ |

## 技术参考（一般不用看）

- **组成部分**：`public/admin/` 全中文三主题单页应用 + `edge-functions/api/[[default]].js` 边缘函数（登录鉴权 + GitHub 读写代理）+ `scripts/cms-dev.mjs` 本地环境（8090 端口）+ `scripts/cms-setup.mjs` 一键配置向导。
- **本地配置**：`.env.local`（已被 gitignore）存放 6 个变量：上面 4 个 + 可选覆盖 `CMS_REPO` / `CMS_BRANCH`。改凭据直接改文件，或重跑向导。
- **登录机制**：账号密码（环境变量校验，常数时间比较），令牌 HMAC 签名、12 小时有效；连续错 5 次锁 15 分钟（滑动窗口，重启进程或重新部署即清零，无解锁后门）。
- **安全底线**：GitHub 令牌只存在服务端环境变量里，浏览器接触不到；所有出站请求走白名单，仅放行 `api.github.com`（含 GraphQL 端点）；`/admin/` 带 `noindex`。
- **发布记录**：所有写操作生成中文 commit message（如「CMS: 更新《标题》」），git 历史即审计日志，删除的内容随时可从历史恢复。
- **手动改配置**：如果你更习惯手工操作，也可以不用向导——4 个环境变量为 `CMS_USERNAME` / `CMS_PASSWORD` / `CMS_SESSION_SECRET`（可用 `openssl rand -hex 24` 生成）/ `CMS_GITHUB_TOKEN`（GitHub → Settings → Developer settings → Personal access tokens，勾 `repo` 权限，只授权本仓库）。
